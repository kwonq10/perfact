Sukima Chrome Extension - Privacy Policy

日本語版は こちら

1. Introduction

This page is the privacy policy for the Chrome extension “Sukima” (the “Extension”), which runs in the Chrome side panel. It explains how the Extension handles information.

This policy applies to the Extension only. It is separate from the privacy policy of the Sukima web app (sukimacalendar.com). If you use the web app, please see its own privacy policy (/privacy).

This is an English translation of the Japanese original at /extension/privacy. Both describe the same implementation.

2. Information we collect

When you sign in with your Google Account, the Extension retrieves only your Google Calendar list and the date and time of your events.

The Extension does not collect your email address or any other personal information.

3. Information retrieved from Google Calendar

The Extension retrieves the following from the Google Calendar API.

  • Calendar list: calendar name, calendar ID, and access role (owner / writer / reader)
  • Event information: start time and end time only

Event titles, attendees, locations, and descriptions are not used to calculate free time.

4. How we use the information

The information we retrieve is used only to calculate and display your free time for the period you specify.

We do not use it for any other purpose.

5. Storage

Calendar information: The Extension does not store calendar information (your calendar list, event date and time, or the calculated free time) in chrome.storage, localStorage, sessionStorage, or IndexedDB.

This information is held in browser memory only while the side panel is open, and it is discarded when you close the side panel.

The Extension's own settings: Separately from the above, the Extension stores information needed to use the Sukima service in your browser's localStorage. Only the following two items are stored.

  • A session token for linking with Sukima, and its expiry
  • A setting retrieved from the Sukima server (whether the free usage limit is enabled), and the time it was retrieved

Neither of these two items contains any calendar content. Both are stored only in your own browser. The linking session token is deleted when you sign out of the Extension. chrome.storage is not used.

6. Data sent to external services

Calendar information is sent only to the Google Calendar API (googleapis.com). Your calendar list, event date and time, and calculated free time are never sent to any server or database operated by the developer.

Separately from that, the Extension communicates with sukimacalendar.com, operated by the developer, in order to use the Sukima service. None of this communication contains any calendar content. The purpose of each request and what it sends are as follows.

  • Checking a setting (/api/ext/config)
    Checks whether the free usage limit is enabled. It sends only the Extension's identifier, has no request body, and does not require sign-in. The check runs when you press the search button, and the result is cached for 5 minutes, so the request is rarely made. No request is sent when you open the side panel, sign in, change search conditions, or move between days.
  • Account linking (/api/ext/link/)
    Sends only the Extension's identifier and a single-use verification string.
  • Usage management (/api/ext/quota/)
    Sends only the linking session token, a reservation ID, and a single-use key.
  • Unlinking (/api/ext/auth/logout)
    Sends only the linking session token.

Of these, the requests for account linking and usage management occur only while the free usage limit is enabled on the Sukima server. When the limit is not enabled, those requests do not occur.

The only thing the Sukima server stores is a record used to manage weekly usage counts while the free usage limit is enabled. It does not store any calendar content.

7. Access tokens

The access token used to call the Google Calendar API is held only in the Extension's JavaScript memory.

The token cache itself is managed by Chrome's chrome.identity mechanism; the Extension does not persist it independently. When you close the side panel, the values the Extension held in memory are discarded.

Note that the Sukima linking session token described in sections 5 and 6 is an entirely separate credential from the Google access token. The Google access token is never sent to the Sukima server.

8. Sharing with third parties

We never sell, provide, or share the information we retrieve with any third party.

9. Advertising, analytics, and tracking

The Extension does not serve advertising, run analytics, or track your behaviour.

10. Cookies

The Extension does not use cookies.

The communication with sukimacalendar.com described in section 6 does not send or receive cookies either; the linking session token is sent in the Authorization header instead.

11. Revoking access and signing out

The Extension has a sign-out function that you can use at any time.

You can also revoke the Extension's access at any time from your Google Account permissions page.

https://myaccount.google.com/permissions

12. Security

Communication with the Google Calendar API uses HTTPS.

The Extension does not have permission to read the content of the web page you are viewing, and it does not read it. Its network access is limited to the Google Calendar API (googleapis.com) and the Sukima service (sukimacalendar.com) described in section 6, and both use HTTPS.

13. Google API Services User Data Policy

The Extension is developed in compliance with the Google API Services User Data Policy.

14. Limited Use compliance

The Extension's use of Google user data complies with the Limited Use requirements. The information we retrieve is used only to provide the intended feature of calculating and displaying free time, and never for other purposes such as advertising or training AI models.

15. Changes to this policy

This policy may change without prior notice as the Extension changes. Any change takes effect when it is published on this page.
